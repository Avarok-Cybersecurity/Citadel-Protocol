Module timing 

Expand description

The protocol’s connect and stage timers, in one place (ROBUST-CONNECTION-MANAGER.md S-P5, S-W1). Each value used to be written where it was read, across three crates, and the ones derived from another (the posting TTL from the connect wait) were derived by hand.

Constants§

FILE_GROUP_CHECK_PERIOD
How often a sender checks each of its outbound file-transfer groups: 1 s. A check is a map lookup and two clock reads per group (plus, while the header is unanswered, a scan of the session’s few outbound groups), so a short period is cheap, and it keeps the time to report a missed deadline close to the deadline itself.
FILE_GROUP_HEADER_ACK_DEADLINE
The deadline, 15 s, for the receiver to answer one file-transfer group’s header. Past it the sender fails the transfer with ErrorCode::FileTransferStalled. The clock runs only while no earlier group of the session is still in flight: every header and payload of a session shares one primary stream, so a header queued behind another group’s payload is not the receiver’s to answer until that payload has drained.
FILE_GROUP_HEADER_UNANSWERED_FAILS_WITHIN
The worst case for reporting an unanswered group header, counted from when the header was first in line: FILE_GROUP_HEADER_ACK_DEADLINE (15 s) plus one FILE_GROUP_CHECK_PERIOD (1 s), because the deadline can pass just after a check: 16 s. This is the figure the workspace UI’s idle timeout for a file send (30 s, the parent repository’s TIMEOUT.FILE_SEND_MS) must exceed, so the coded failure is what a person sees; it leaves 14 s between them. The SDK cannot read the UI’s constant; the parent asserts the ordering.
P2P_CONNECT_TIMEOUT
How long a P2P dial waits for the peer’s answer through the server.
P2P_STAGE_TIMEOUT
One P2P path stage planned without a stamped plan (the hole punch with its QUIC handshake, or one TURN attempt), and the wait for the peer at a retry’s rendezvous.
POSTING_SLACK
How long the server holds a dial’s posting beyond the dialler’s own wait, so the answer to a dial still waited for is never refused for want of its posting.
POSTING_TTL
How long the server holds a P2P dial’s posting.
TRANSPORT_CONNECT_TIMEOUT
One transport connect step to a server: a TCP connect, a TLS handshake, a QUIC upgrade, a WebSocket handshake.
TURN_CONNECT_TIMEOUT
A connect to a TURN server, which may sit across the internet rather than beside the Citadel server: two and a half transport steps.
