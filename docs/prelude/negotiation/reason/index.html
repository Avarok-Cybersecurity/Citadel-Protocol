Module reason 

Expand description

Why a P2P connection was closed on purpose.

A deliberate drop and a lost link used to reach the peer identically, so the peer could only redial. The reason travels two ways:

  • in PeerSignal::Disconnect.reason. The server does not relay a peer’s Disconnect as bytes: it decodes it, builds the signals it sends from its fields, and copies the reason across.
  • on the connection’s own negotiation lane, end to end, before the Disconnect is sent: the peer’s SDK records it against the connection (PeerClosing) and acknowledges it, and only then does the closing side disconnect. Whatever the server rebuilt, the peer reports the Disconnect that follows with the reason it recorded.
